# 后续Draft提案：真实地块进入前的准备

工程已接入 [FieldSignal 仓库](https://github.com/gluttonsama-cloud/FieldSignal)，在 [Draft PR #1](https://github.com/gluttonsama-cloud/FieldSignal/pull/1) 持续审阅，已有锁定依赖的独立 CI；尚未合并或部署。以下为真实田块进入前仍需完成的工作。

1. 公开小窗已验证本地S2预处理契约：逐资产scale/offset、SCL/nodata、10m/20m网格对齐和来源记录。真实地块仍需可信mask生成与polygon-raster覆盖校验；公开AOI不能替代真实油菜田。
2. 用户提供获授权的沙洋地块边界、作物/播期/季节后，先做少量历史S2观测，审查缺测和数据质量，再看统计候选；不能用单期图像做异常或病因结论。
3. 气象只作粗网格回溯上下文，保留UTC日支持、分辨率、延迟与缺失值。SAR身份、额度与条款另行确认，不自动注册、付费或借用凭据。
4. 组织真实巡田，明确农户同意、照片访问、坐标保护与保留时间。人工标签需审核且允许“不确定”，先形成可追溯事件，再算指标。
5. 评估服务端PostGIS及手机PWA断网体验，之后决定原生壳/原生App。先完成移动现场任务，不堆深度学习模型。
6. 罗田仅作为事先保留的外部测试区；按地块/时间/区域隔离训练与测试，记录数据泄露防护。尚无已获合作和标签。

验收：地块来源可追溯；无观测/低质量/过期不会变绿色正常；失败重试不丢草稿或重复完成；公开与synthetic数据不冒充真实农情；指标仅引用实际可复核实验。

## 断网重开页面：待验证方案，尚未启用

- 仅为 `/field` 准备按构建版本固定的HTML、哈希JS/CSS与图标；严格白名单，不缓存API、服务端照片、地块或其他用户数据，不新增后台上传。
- 必须先在线完整准备；首次离线访问、缓存未完成或被浏览器清理时不可承诺打开。准备状态须实际确认，不能只看注册成功。
- 新版本等待旧页面退出，提示先保存草稿再关闭重开；不用强制激活、抢占页面或混用新HTML与旧资源。只清理自己的过期静态缓存。
- 草稿沿用IndexedDB v2，不清库、不自动迁移；管理端也共享草稿库，未来跨版本兼容不能只依赖Service Worker等待机制。
- Node/HTTP只能检查白名单、资源完整性与模拟生命周期；真实浏览器仍需验首次准备、断网刷新、缓存失败/清理、旧页更新和照片草稿恢复。当前浏览器环境受限，故暂不启用。
- 本机监听与可信主机限制保持不变。手机的localhost不是电脑服务，普通局域网HTTP也不等于安全上下文；此方案不代表已可在真实手机部署使用。
